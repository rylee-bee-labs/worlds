# Dev reset — ephemeral sessions by design

> **Status:** Reference · **Verified:** 2026-09-26 · **Canonical for:** the `scripts/reset-dev.sh` wipe procedure and its safety rules · **Read this if:** you need to return a development instance to a clean first-run state.

**In short:** how to wipe a development instance back to the setup wizard, and the safety rules that keep the wipe from touching tracked files or production. Default is dry-run; nothing is removed without `--yes-i-wipe`.

Worlds is a **universal** self-hosted app. During development, sessions
are **ephemeral**: we wipe generated state and return to a clean first-run
(setup wizard) rather than accumulating personal or experimental data.

Your real data is in your separate data repo and is **not** part of this
repository. Git/GitHub is the time machine for code; `data/` is disposable.

## Wipe a dev instance

```bash
scripts/reset-dev.sh                 # dry-run: shows exactly what would go
scripts/reset-dev.sh --yes-i-wipe    # actually wipe local ./data
scripts/reset-dev.sh --volume pw_data --yes-i-wipe   # wipe a compose volume
```

After a wipe, the next `docker compose up` (or local run) presents the
**first-run setup wizard**, which provisions invisibly and offers local-token
or your-own-SSO (OIDC, e.g. Authelia) auth.

## Safety rules (do not weaken)

- **Default is dry-run.** Nothing is removed without `--yes-i-wipe`.
- Only **untracked generated state** is touched (local `data/` or a named
  Docker volume). Never git-tracked files, never the repo, never code.
- Refuses targets that look **production** unless you also pass
  `--i-know-this-is-prod`.
- Prints exactly what it will remove, before removing it.

## What is regenerated vs lost

| Item | After reset |
|---|---|
| `PW_API_TOKEN` (data/.env) | regenerated by first-run |
| stores (world/journal/etc.) | recreated empty by first-run |
| FTS index (memory.fts5.db) | rebuilt from journal (empty until you write) |
| sessions | dropped (ephemeral by design) |
| your separate data repo | untouched, always |
