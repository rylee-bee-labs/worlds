# T7: Sonarr, Radarr, Lidarr, Prowlarr recipes
Read `briefs/COMMON-R.md` first. All four use header `X-Api-Key`.

**sonarr** (env `SONARR_API_KEY`, port 8989, API `/api/v3`). Requests: `sonarr.calendar` GET `/api/v3/calendar` query `start={today}`, `end={today+7d}`, `includeSeries=true`, `unmonitored=false` (a JSON list of episodes: `title`, `seasonNumber`, `episodeNumber`, `airDateUtc`, `series: {title}`); `sonarr.queue` GET `/api/v3/queue` query `pageSize=1` (`{totalRecords, records: [...]}`). One card `tv`, title "TV", group `life`, `requests: [sonarr.calendar, sonarr.queue]`. Fields: "Airing this week" = count of `$.calendar`; "Next up" = `$.calendar[0].series.title`; "Airs" = `$.calendar[0].airDateUtc` as relative_time; "Downloading" = `$.queue.totalRecords` as number, unit "in queue". Meter: type `marks`, items `$.calendar[*].series.title`. No status map (reachable = healthy).
Governed wiring: two actions in `actions/`: `sonarr-refresh-series` (name "Refresh all series") and `sonarr-missing-search` (name "Search for missing episodes"), each `access: write`, `approval: always`, `exposed: false`, `scope: sonarr`, `idempotency: none`. Each points at a write request: `sonarr.refresh-series` and `sonarr.missing-search`, both `method: POST`, path `/api/v3/command`, `body: {"name": "RefreshSeries"}` and `{"name": "MissingEpisodeSearch"}`, `effect: write`, `ttl_s: 0`. In `recipe.yaml` `note`, say the two command names were taken from the Sonarr API docs and not run against a live instance.

**radarr** (env `RADARR_API_KEY`, port 7878, `/api/v3`). Requests: `radarr.calendar` GET `/api/v3/calendar` query `start={today}`, `end={today+30d}`, `unmonitored=false` (list of movies: `title`, `inCinemas`, `digitalRelease`, `physicalRelease`); `radarr.wanted` GET `/api/v3/wanted/missing` query `pageSize=1` (`{totalRecords, records}`). Card `movies`, title "Movies", group `life`, both requests. Fields: "Coming up" = count of `$.calendar`; "Next film" = `$.calendar[0].title`; "Missing" = `$.wanted.totalRecords` number unit "wanted". Meter `marks` over `$.calendar[*].title`.

**lidarr** (env `LIDARR_API_KEY`, port 8686, `/api/v1`). Request `lidarr.calendar` GET `/api/v1/calendar` query `start={today}`, `end={today+30d}`, `includeArtist=true`, `unmonitored=false` (list of albums: `title`, `releaseDate`, `artist: {artistName}`). Card `music`, title "Music", group `life`. Fields: "New albums" = count of `$`; "Next album" = `$[0].title`; "By" = `$[0].artist.artistName`; "Out" = `$[0].releaseDate` relative_time. Meter `marks` over `$[*].title`.

**prowlarr** (env `PROWLARR_API_KEY`, port 9696, `/api/v1`). Request `prowlarr.health` GET `/api/v1/health` (a list; each `{source, type, message}` with `type` one of `ok`, `notice`, `warning`, `error`; an empty list means no problems). Card `indexers`, title "Indexers", group `machine`. Status: `path: $[*].type`, `mode: any`, `healthy: [ok, notice]`, `needs_attention: [warning, error]`, `empty: healthy`. Fields: "Problems" = count of `$`. Meter `marks` over `$[*].source`. Samples: empty list (healthy), one `warning` (needs_attention), `{__status: 500}` (unavailable).
