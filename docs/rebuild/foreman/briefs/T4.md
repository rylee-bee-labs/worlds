# T4: Connect, Memory and Settings skeletons
Read `briefs/COMMON.md`, `ui/src/fd/{Tabs,prefs,fixtures,types}.ts(x)`, `ui/src/test/fd-screens.test.tsx`. `Tabs.tsx` is done: use it, do not edit it.

Create `ui/src/fd/Connect.tsx`, `Memory.tsx`, `Settings.tsx`, each a named export with no props, each starting with an `<h1>` (Connect, Memory, Settings) and then the content. Append styles to `ui/src/fd/fd.css` under `/* screens */` (shared: append only).

**Connect** tabs, in order: Requests, Providers, Recipes, Actions, Advanced. Requests, Providers, Recipes: one short sentence saying it arrives with the Connect API ("Saved requests will run here."), nothing else. Actions: list `sampleBindings`. A read binding shows its name and "Read" only. A write binding has a button with accessible name `Run: {name}`. It opens `<div role="dialog" aria-modal="true" aria-labelledby=…>` titled "Run {name}?" with "Confirm" and "Cancel" buttons; focus moves into the dialog, Escape cancels, a cancel returns focus to the Run button. Confirm closes the dialog and shows `<p role="status">` with the receipt, e.g. "Restart Sonarr: SUCCEEDED" using the binding's `outcome` (SUCCEEDED, FAILED or UNKNOWN; show UNKNOWN as "UNKNOWN: the result was not confirmed"). Always show the text "Sample data" in this panel. Advanced: `sampleSecrets` as names with the word "Set" or "Not set" (text, not colour). A button `Replace {name}` reveals `<input type="password" autocomplete="off">` labelled `New value for {name}`, always empty, plus Save and Cancel; Save just closes it and clears the input (nothing is stored or shown). Never display or log a secret value.

**Memory** tabs, in order: Kept, Later, Records, History, Find. Kept, Later, History: one short sentence ("Nothing kept yet."). Records: a button "Confirm it's you" with a one-line explanation; it does nothing yet. Find: `<input type="search">` labelled "Search Memory" and the line "Search runs on this device."

**Settings** sections with `<h2>`s: Experience, Comfort, Assistant. Radio groups (native `<input type="radio">` with `<label>`, wrapped in `<div role="radiogroup" aria-label=…>`), each bound to `usePrefs()`: "Experience pack" (None, Station), "Theme" (Starfield, Daylight, Plain), "Density" (Calm, Standard, Detailed), "Words" (Minimal, Short, Full), with a one-line description per group (Minimal: facts only; Short: a short meaning; Full: sentences and freshness). Text only: "Motion follows your device setting." Assistant: the label "Assistant" and the value "Not installed". Every radio row is at least 44px tall and has a visible focus ring.

Acceptance: `cd ui && npx vitest run --project unit src/test/fd-screens.test.tsx`
